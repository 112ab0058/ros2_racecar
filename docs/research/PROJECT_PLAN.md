## 1. 前提

| 項目 | 內容 |
|---|---|
| 目的 | 專題研究「多感測器融合感知與智慧決策系統」。**不參加 WRO 比賽**，規則只當參考，不是大問題的違規都可以接受 |
| 期限 | **2026 年 11 月中**完成（約 4 週） |
| 車 | WHEELTEC R550 mini akm（阿克曼）+ Jetson Orin Nano，見 [R550_HARDWARE.md](../real/R550_HARDWARE.md) |
| 場地 | **已經建好，不太能改**：160 × 160 cm，中間島 40 × 40 cm，車道約 60 cm，牆高 10–15 cm（[FIELD_PLAN_160CM.md](../sim/FIELD_PLAN_160CM.md)，實際尺寸待確認） |
| 教授的期待 | 車 + 場地 + 建圖導航 + AI |

**一句話主軸**：在阿克曼實車和實體場地上，用多感測器融合做建圖、定位與導航，再加上 AI 做智慧決策。

## 2. 系統架構

```text
┌─ Jetson Orin Nano（SoC / SBC）：Ubuntu 24.04 + ROS 2 Jazzy ─────────────────────┐
│                                                                                  │
│  感測器 driver        感知                 定位 / 建圖          決策 / 導航       │
│  光達 N10P ──▶ /scan ──────────────────▶ slam_toolbox ──▶ 地圖                    │
│  相機 C70  ──▶ 影像 ─▶ HSV 顏色辨識                │            AI 任務層（第 4 節）│
│                       （線、色塊）          EKF（robot_localization）    ↓         │
│  底盤 driver ─▶ /odom、/imu ──────────────▶ encoder + IMU 融合     Nav2（阿克曼）  │
│       ▲                                                              ↓            │
│       └──────────────────────── /cmd_vel（v、ω）◀──────────────────────┘           │
└───────┬──────────────────────────────────────────────────────────────────────────┘
        │ USB 串口 3，115200，指令 11 bytes / 回授 24 bytes
┌───────┴─ C30D 控制板：STM32F407（MCU / SBM）+ FreeRTOS（RTOS）─────────────────┐
│  (v, ω) → 運動學逆解 → 後輪 PI 控制 + 前輪舵機；encoder、IMU、電壓 → 回傳         │
└──────────────────────────────────────────────────────────────────────────────────┘
```

| 名詞 | 在我們車上 |
|---|---|
| SoC / SBC | Jetson Orin Nano（大腦：需要算力、不要求準時） |
| MCU / SBM | C30D 上的 STM32F407（小腦：算力低、要求準時） |
| RTOS | STM32 上的 FreeRTOS（廠商寫好，用 Keil5 寫、FlyMcu 燒錄） |
| ROS | Orin 上的 ROS 2 Jazzy（通訊框架，不是作業系統） |
| Driver | 軟體：Orin 上把 `/cmd_vel` 和串口封包互相翻譯的 node；硬體：C30D 上的馬達驅動晶片 |
| Perception | 光達看障礙物和牆；相機用 HSV 看顏色（線、色塊） |
| Localization / Fusion | encoder + IMU 用 EKF 融合；slam_toolbox 用光達在地圖上定位 |
| Planning / Navigation | Nav2：Smac Hybrid-A* 規劃器 + Regulated Pure Pursuit 控制器（阿克曼不能原地轉，不能用預設的差速設定） |
| Decision | AI 任務層 + 狀態機 |
| Action / Control | `/cmd_vel` → STM32 的運動學和 PI |

## 3. 已經決定的事

| 決定 | 原因 |
|---|---|
| **建圖導航用 slam_toolbox + Nav2，不從頭自己寫** | 4 週內自己寫 SLAM 做不完。深度放在：在阿克曼實車上調通、懂原理、用實驗證明效果 |
| **不用 YOLO** | 避障用光達就夠（距離準、不怕光線）；顏色用相機的傳統 HSV 辨識，不需要 AI |
| STM32 韌體用廠商的，**只讀不改** | 已經能用，改壞風險高 |
| 底盤 ROS driver **自己寫**（`wro2026_base_r550`） | 要有逾時停車、限速、低電壓這些安全機制；協定已用官方文件驗證 |
| 光達 driver 用廠商的，相機用現成 UVC 套件 | 通用的東西用現成的 |
| WRO 規則不管（例如後輪兩顆馬達的電子差速、無線、尺寸重量） | 不比賽 |

**觀念提醒（2026-10-16 討論時更正）**：光達不能完全取代相機。
- N10P 是 **2D 光達，只看得到安裝高度的那一個水平面**，比它低的牆和障礙物看不到
- 光達也看不到顏色和地上的線
- 所以：避障交給光達，顏色交給相機

## 4. AI 用在哪裡（待教授決定）

| | A. 語言指令任務規劃（LLM） | B. 模仿學習駕駛（Behavior Cloning） |
|---|---|---|
| 做法 | 使用者用自然語言下指令，LLM 轉成**事先定義的地點和動作清單**，交給 Nav2 執行。LLM 不能直接控制速度 | 人遙控開車，錄「光達掃描 → 速度、轉向」；訓練小神經網路模仿，和規則式控制、Nav2 比較 |
| 亮點 | 展示效果好；「AI 理解指令、傳統演算法保證安全」的分層 | 研究味重，有定量比較 |
| 4 週風險 | 低（約 1 週），但要 Nav2 先能動 | 中（資料品質、實車調整） |

**建議**：A 當主線，B 時間夠再做。A 建立在建圖導航上，前面的工作不會白費。

## 5. 專題的研究內容（報告的實驗）

| 實驗 | 比較什麼 | 用到 |
|---|---|---|
| 定位融合 | 只用輪子 / 只用 IMU 算角度 / EKF 融合，繞固定路線回到起點的位置和角度誤差 | encoder、IMU、`robot_localization` |
| 建圖品質 | 地圖量出的場地尺寸和捲尺量的差多少；有 EKF 和沒有 EKF 的地圖比較 | slam_toolbox |
| 導航 | 到點成功率、到點誤差、花費時間 | Nav2（阿克曼設定） |
| AI 決策 | 依第 4 節選的方向（指令成功率，或和規則式控制比較完成率、碰撞次數） | |
| （選做）自己寫 Pure Pursuit | 和 Nav2 的 Regulated Pure Pursuit 比較路徑追蹤誤差 | 證明懂原理 |

## 7. 要先確認的風險

| 風險 | 怎麼確認 | 影響 |
|---|---|---|
| **光達掃描面高於牆**（牆 10–15 cm） | 量地面到光達中心的高度 | 看不到牆就無法建圖。解法：加高牆、或降低光達 |
| **車在場地轉不過去**（車道約 60 cm） | 量最大轉向角，算最小轉彎半徑（最大轉角 30° 時約 0.33 m，20° 時約 0.48 m） | 轉不過去，Nav2 就規劃不出路徑 |
| Orin 電源 | 方案：電池直接接 DC 線（10–12.6 V 在 Orin 的 9–20 V 範圍內，要加保險絲），或 PD 行動電源 | 沒解決就只能拖線 |
| Nav2 和 OpenCV 衝突 | 裝 Nav2 會把 Ubuntu 的 OpenCV 4.6 開發套件換成 NVIDIA 4.8；建議用 apt pin 固定 4.6（先做 SD 卡映像） | 第 3 週前要解決 |
| 資料包缺 STM32 原始碼、Mini 硬體說明 | 重新下載或跟廠商要 | 尺寸、逾時停車要靠自己量和測 |
