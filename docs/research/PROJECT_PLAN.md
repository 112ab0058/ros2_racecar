## 2. 系統架構

```text
┌─ Jetson Orin Nano：Ubuntu 24.04 + ROS 2 Jazzy ───────────────────────────────────────────┐
│                                                                                          │
│  感測器 driver            感知 / 融合               地圖 / 定位          決策 / 導航          │
│  N10P 光達 ─▶ /scan ─▶ 遮掉車身的角度 ─────────▶ slam_toolbox 建圖 ─▶ 地圖                 │
│                                                  AMCL 在地圖上定位        AI 任務層（LLM）   │
│  C70 相機 ─▶ 影像 ─▶ HSV 顏色辨識（看 AI 需求）                              │ 目標點       │
│  底盤 ─▶ /odom、/imu ─▶ EKF（robot_localization）─▶ odom→base_link    Nav2：             │
│     ▲                                                                  Hybrid-A* 全域規劃  │
│     │                                                                  Pure Pursuit 追蹤  │
│     └──────────── /cmd_vel（v, ω）◀─ 安全層（逾時、限速）◀─ 遙控 / Nav2 ◀─┘                 │
└─────┬────────────────────────────────────────────────────────────────────────────────────┘
      │ USB 串口，115200，指令 11 bytes / 回授 24 bytes（20 Hz）
┌─────┴─ C30D：STM32F407 + FreeRTOS（廠商韌體，只讀不改）──────────────────────────────────┐
│  (v, ω) → 阿克曼運動學 → 後輪 PI 速度控制 + 前輪舵機；encoder、IMU、電壓 → 回傳              │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

| 名詞 | 在我們車上 |
|---|---|
| SoC / SBC | Jetson Orin Nano（大腦：算力高、不要求準時） |
| MCU | C30D 上的 STM32F407（小腦：算力低、要求準時） |
| RTOS | STM32 上的 FreeRTOS（廠商寫好） |
| ROS 2 | Orin 上的通訊框架（不是作業系統） |
| Driver | 把 ROS topic 和串口封包互相翻譯的 node；硬體上是 C30D 的馬達驅動晶片 |

## 3. 模組與演算法總表

**標記**：**主線** = 一定做；**比較** = 實驗時拿來和主線比；**理論** = 報告寫原理，不實作；**選做** = 時間夠才做；**不做** = 已決定不做（附原因）。

### 3.1 底層與感測器

| 模組 | 用什麼 | 標記 | 狀態 / 說明 |
|---|---|---|---|
| 底盤回授 | 自己寫 `wro2026_base_r550`：`/odom`、`/imu/data`、`/battery` | 主線 | ✅ 2026-10-16 |
| 底盤指令端 + 安全層 | 自己寫 `base_node` + `CommandGate`：`/cmd_vel` 逾時 0.3 s 停車、限速、回授遺失停車、低電壓拒絕、限時、不原地轉 | 主線 | 程式寫好（2026-10-17）；**待架空驗證** |
| 底層速度控制 | STM32 韌體的 PI 控制（後輪）+ 舵機（前輪） | 理論 | 廠商的，只讀不改；原理看廠商〈运动控制与PID〉 |
| 遙控 | 鍵盤遙控（自己寫小 node，或裝 `teleop_twist_keyboard`，裝前列清單確認） | 主線 | 建圖要靠遙控繞場地 |
| 光達 driver | 自己寫 `wro2026_lidar_n10p`（協定照官方） | 主線 | ✅ 2026-10-17，`/scan` 10 Hz、480 格 |
| 光達遮罩 | driver 參數 `mask_sectors_deg`（例如 `150:210`），範圍內的光束設成 inf | 主線 | 程式已加（2026-10-18）；Orin 裝好後錄一圈決定角度。Orin 一定會擋到光達正後方一小段，車子主要往前開，後方少一塊對建圖、導航影響小；**倒車時後方看不到**，Nav2 要限制倒車 |
| URDF / TF | 自己寫 `wro2026_description`，`base_link` = 後軸中心 | 主線 | ✅ 2026-10-17 |
| 相機 | C70 + 現成 UVC 套件；HSV 顏色辨識（OpenCV） | 選做 | 用途看 AI 方向（例如色塊當目標點）；OpenCV 怎麼裝要先決定 |
| 監看 | Foxglove（唯讀 bridge） | 主線 | ✅ |

### 3.2 定位與建圖

| 模組 | 用什麼 | 標記 | 說明 |
|---|---|---|---|
| 里程計校正 | `vx_scale`、`wz_scale` | 主線 | 目前 0.814 是架空量的，要在地面重測 |
| 感測器融合 | **EKF**（`robot_localization`）：encoder 的 vx + IMU 的 wz | 主線 | 已安裝。「定位融合」實驗的主角 |
| 2D 建圖 | **slam_toolbox** | 主線 | 已安裝。圖最佳化（graph-based）SLAM，有 loop closure |
| 建圖比較 | gmapping（粒子濾波）、Cartographer | 理論 | 廠商有〈三种2D建图算法对比〉；報告說明為什麼選 slam_toolbox |
| 地圖上定位 | **AMCL**（自適應蒙特卡羅定位，Nav2 內建） | 主線 | 粒子濾波：撒粒子猜位置，跟光達比對、留下像的 |
| 定位比較 | slam_toolbox 的定位模式 vs AMCL | 選做 | 同一條路線比誤差 |
| 視覺 SLAM | ORB-SLAM | 不做 | 2D 光達建圖比較準、比較穩，時間也不夠 |

### 3.3 規劃與控制（Nav2）

| 模組 | 用什麼 | 標記 | 說明 |
|---|---|---|---|
| 代價地圖 | **Costmap**（靜態層 + 障礙層 + 膨脹層） | 主線 | 車道只有 60 cm，膨脹半徑是關鍵參數 |
| 全域規劃 | **Smac Hybrid-A\***（考慮最小轉彎半徑） | 主線 | 阿克曼不能原地轉，一般的格點規劃會規劃出走不了的路 |
| 全域規劃原理 | Dijkstra、A\* | 理論 | Hybrid-A\* 的基礎；廠商有 `nav_Astar&dijkstra.py` 可以跑來理解 |
| 路徑追蹤 | **Regulated Pure Pursuit (RPP)** | 主線 | 幾何追蹤：看前方一個點，算出要轉的弧線；會在轉彎、靠近障礙時自動減速 |
| 路徑追蹤比較 | MPPI（取樣式模型預測控制，支援阿克曼） | 選做 | 和 RPP 比追蹤誤差、平順度 |
| 自己寫 Pure Pursuit | 自己的 node，訂閱 Nav2 的路徑、發 `/cmd_vel` | 選做 | 和 RPP 比，證明懂原理 |
| 局部規劃原理 | DWA、TEB | 理論 | DWA 是給差速車的；TEB 支援阿克曼，但 Jazzy 沒有人維護。報告說明為什麼不用 |
| 多點導航 | Nav2 waypoint follower | 主線 | AI 任務層會用到 |

### 3.4 決策（AI）

| 方向 | 做法 | 標記 |
|---|---|---|
| **A. LLM 任務規劃** | 使用者用自然語言下指令（例如「先去 A 再回起點」），LLM 轉成**事先定義好的地點和動作清單**，交給 Nav2 多點導航。**LLM 不能直接控制速度**，安全交給傳統演算法 | 建議主線（等教授決定） |
| B. 模仿學習 | 人遙控開車，錄「光達掃描 → 速度、轉向」，訓練小神經網路模仿，和 Nav2 比完成率、碰撞次數 | 選做（等教授決定） |
| 狀態機 | 任務流程：待命 → 導航 → 到點動作 → 下一點 → 結束；失敗時重試或停車 | 主線（A、B 都需要） |
| LLM 放哪 | Orin 本機跑小模型（廠商有本地部署 DeepSeek 的教學）或雲端 API | 待決定 |
| 不做 | YOLO（避障用光達就夠，顏色用 HSV）、KCF 追蹤、語音、多機編隊、人體骨架 | 不做 |

## 5. 要調的參數

| 階段 | 參數 | 怎麼決定 |
|---|---|---|
| 底盤安全層 | 最高速度、加速度上限、逾時 | 先保守（0.3 m/s、0.3 s），架空和地面測完再放寬 |
| 里程計 | `vx_scale`、`wz_scale` | 地面直走 2 m 比捲尺；繞一圈比 IMU 的角度 |
| IMU | gyro 偏差、covariance；`imu_link` 軸向 | 靜止錄 1 分鐘算平均和變異數；轉彎時比 gyro z 和 `/odom` 的 wz |
| 光達 | 遮罩角度、`range_min` | Orin 裝好後錄一圈，最近的點（目前約 0.13 m）是不是自己的車 |
| EKF | 融合哪些量、各自的 covariance | 實驗 E1 |
| slam_toolbox | 地圖解析度（場地小，考慮 2–2.5 cm）、最小移動距離 / 角度、loop closure | 實驗 E2 |
| AMCL | 粒子數、雜訊模型、初始位置 | 實驗 E3 |
| Costmap | 車子外形（footprint）、膨脹半徑、障礙層更新頻率 | 車道 60 cm，太大會規劃不出路 |
| Hybrid-A\* | 最小轉彎半徑、是否允許倒車、角度解析度 | 最小轉彎半徑由步驟 7 量出來 |
| RPP | 前視距離、速度、轉彎減速、接近目標減速 | 實驗 E3、E5 |

## 7. 已經決定的事

| 決定 | 原因 |
|---|---|
| **建圖導航用 slam_toolbox + Nav2，不從頭寫** | 時間內自己寫 SLAM 做不完；深度放在調通、懂原理、實驗證明 |
| **不用 YOLO** | 避障用光達就夠（距離準、不怕光線）；顏色用 HSV |
| STM32 韌體用廠商的，**只讀不改** | 已經能用，改壞風險高 |
| 底盤 driver **自己寫** | 要有逾時停車、限速、低電壓這些安全機制；協定已用官方文件驗證 |
| 光達 driver **自己寫**（協定照官方） | 官方 driver 是 C++、只測過 Foxy / Humble，要多裝約 1.4 GB；我們只需要 `/scan`（2026-10-16） |
| 規劃器用 Hybrid-A\* + RPP，不用 DWA / TEB | 阿克曼不能原地轉；TEB 在 Jazzy 沒有維護 |
| WRO 規則不管 | 不比賽 |
| 3 個套件已安裝（robot-localization、slam-toolbox、foxglove-bridge） | 2026-10-17，新增 204、移除 0 |

**觀念提醒**：光達不能完全取代相機。N10P 是 2D 光達，只看得到 15 cm 高的那一個水平面，也看不到顏色和地上的線。所以避障交給光達，顏色交給相機。
