## 1. 整台車的分工

```text
上層決策（Orin，ROS 2）      ──下發三軸目標速度──▶   底層執行（C30D 上的 STM32）
  需要算力、實時性要求不高   ◀──回傳里程計、IMU、電壓──   算力低、實時性要求高
                                                          ├─ 運動學逆解 → 各輪目標速度
感測（光達、相機）直接接 Orin                              ├─ PI 控制 → 馬達 PWM
                                                          └─ 舵機 → 前輪轉向
```

**重點**：Orin 不直接控制馬達，只告訴 STM32「我要多快、轉多快」，剩下的由 STM32 做。（來源：開發手冊第 2、3 章）

## 3. 開機流程

1. 確認電池電壓 > 10 V，低於 10 V 要先充電（快速手冊）
2. 打開主開關，蜂鳴器短響一聲
3. **前 10 秒是初始化**：LED 快閃，STM32 在取樣 IMU 零點並去除漂移（開發手冊 2.8）。**這段時間車子不能動、不要碰**，不然 IMU 零點會偏，之後建圖會歪
4. 10 秒後 LED 變成正常閃爍，才能控制
5. OLED 左下角顯示控制模式，**開機預設是 ROS 模式**（開發手冊第 5 章）

| OLED 顯示 | 控制來源 |
|---|---|
| ROS | 串口 3（ROS 主機）← 我們要用的 |
| USART | 串口 1 |
| APP | 藍牙手機 APP |
| PS2 | PS2 手柄 |
| R-C | 航模遥控 |
| CAN | CAN 匯流排 |

**驗證**：開機後拍 OLED，確認第一行的車型是阿克曼、左下角是 ROS。

## 4. 運動學：阿克曼怎麼換算（專題報告可以直接用）

R550 mini akm 是**後輪兩顆馬達驅動、前輪用舵機轉向**。

| 符號 | 意義 |
|---|---|
| W | 輪距（左右後輪的距離） |
| L | 軸距（前後輪的距離） |
| K | 前輪兩個轉向節的距離 |
| v、ω | 車子的前進速度（m/s）、轉向角速度（rad/s） |
| v_L、v_R | 左、右後輪的速度 |
| α | 左前輪的轉角（控制量） |
| R | 轉彎半徑 |

**逆運動學**（已知要的 v、ω，求輪子要怎麼動）：
- 轉彎半徑：`R = v / ω`
- 左前輪轉角：`α = atan( L / (v/ω − K/2) )`　（式 3-3）
- 後輪速度：`v_L = v − ω·W/2`、`v_R = v + ω·W/2`　（式 3-4）

**正運動學**（已知輪子怎麼動，求車子的 v、ω，這就是里程計）：
- `v = (v_L + v_R) / 2`　（式 3-6）
- `ω = (v_R − v_L) / W`　（式 3-8）

**理想的內外輪轉角關係**：`cot β − cot α = K / L`（式 3-2）。只要控制一個前輪，另一個就跟著決定。

**推論**：
- `ω = 0` 時 R 是無限大，`α = 0`，車子直走
- `v = 0` 時公式不成立：**阿克曼不能原地旋轉**。所以我們的控制器不能依賴原地轉
- 最小轉彎半徑由最大轉角決定

**驗證**：量 W、L、K，代入公式算出最小轉彎半徑，再實際開一圈量地上的圓。

（來源：運動學 PDF 第 3 章，第 6–7 頁）

## 5. 馬達怎麼控制

**輪子線速度**（開發手冊 4.1）：

```text
線速度 = 每秒 encoder 計數 × 輪子周長 / encoder 精度
程式：MOTOR_A.Encoder = Encoder_A_pr × CONTROL_FREQUENCY × Wheel_perimeter / Encoder_precision
```

`Encoder_precision` 包含線數、減速比和倍頻。例如 500 線的 GMR encoder，AB 兩相 4 倍頻、減速比 1:30，馬達輸出軸轉一圈會數到 500 × 4 × 30 = 60000 個脈衝（這個減速比只是手冊舉的例子，R550 mini 實際的值要查程式）。

**增量式 PI 控制**（開發手冊 4.2）：

```text
誤差 = 目標速度 − 實際速度
PWM += Kp × (這次誤差 − 上次誤差) + Ki × 這次誤差
PWM 限制在 ±7200
```

「增量式」是指每次只算 PWM 要「增加多少」，而不是直接算 PWM 的值。

**驗證**：馬達 OFF、用手推車子，看 ROS 回傳的速度是否合理（第 2 階段）。

## 7. 串口通訊協定（Orin 和 STM32 怎麼講話）

來源：【協定文件】、【阿克曼指令】。這是寫底盤 driver 最重要的一節。

### 7.1 基本設定

- 接 C30D **中間的 USB-C（串口 3）**，**115200 baud**。開機預設就是 ROS 模式，ROS 控制的優先權最高
- **不要用串口 1 跟 ROS 通訊**：串口 1 是燒錄用的，STM32 重新上電時收到資料會被當成燒錄封包，會卡死
- 收到串口 1 的資料後，OLED 左下角會變成「USART」
- 板子上的 USB 轉串口晶片是 CH9102 或 CP2102（Windows 要裝資料包裡的 CH343SER 驅動）

### 7.2 Orin → STM32：控制指令（11 bytes）

| byte | 內容 | 型別 |
|---|---|---|
| 0 | 幀頭 `0x7B` | uint8 |
| 1、2 | 保留位，**沒有意義**，送 0 | uint8 |
| 3–4 | X 目標速度，mm/s（往前為正） | int16 |
| 5–6 | Y 目標速度，mm/s（只有全向車用，我們送 0） | int16 |
| 7–8 | Z 目標角速度，**rad/s × 1000**（左轉為正） | int16 |
| 9 | 檢查碼：byte 0–8 全部 XOR | uint8 |
| 10 | 幀尾 `0x7D` | uint8 |

**範例**（文件 3.1 節）：前進 100 mm/s = `7B 00 00 00 64 00 00 00 00 1F 7D`
- `00 64` = 100
- 後退 100 mm/s 要用**二補數**：65536 − 100 = 65436 = `FF 9C`

### 7.3 STM32 → Orin：狀態回授（24 bytes，預設 20 Hz）

| byte | 內容 | 換算 |
|---|---|---|
| 0 | `0x7B` | |
| 1 | flag_stop：**0 = 馬達使能**，其他 = 失能（Motor 開關 OFF 時應該不是 0，待驗證） | |
| 2–7 | X、Y、Z 速度 | mm/s；rad/s × 1000 |
| 8–13 | 加速度計 X、Y、Z 原始值 | ÷ 1672 = m/s²（16384 LSB/g ÷ 9.8） |
| 14–19 | 陀螺儀 X、Y、Z 原始值 | ÷ 3753 = rad/s |
| 20–21 | 電池電壓 | mV |
| 22 | byte 0–21 的 XOR | |
| 23 | `0x7D` | |

**速度從哪來**：STM32 用 encoder 算出每個輪子的速度，再用**正運動學**（第 4 節）算出車子的 X、Z 速度。這就是我們的輪式里程計。

**手算練習**（文件的範例）：`7B 00 00 9B 00 00 FF DF …`
- X 速度：`00 9B` = 155 mm/s
- Z 速度：`FF DF` 最高位是 1，是負數，65536 − 0xFFDF = 33 → −0.033 rad/s（往右轉）

### 7.4 阿克曼版的 Z：送角速度，STM32 自己算轉角

**這是之前最大的疑問，答案是 (v, ω)。**
- 官方文件：阿克曼車型收到 X、Z 目標速度後，由 STM32 換算成前輪轉角，並檢查轉彎半徑有沒有小於最小轉彎半徑（文件 4.4 節）
- 所以 ROS 的 `/cmd_vel`（`linear.x`、`angular.z`）可以**直接**放進封包，不用自己算轉角。換車時上層程式也不用改
- 第三方 driver 的「轉向角 × 1000 / 2」模式，官方文件裡沒有，**不用**

想用轉角下指令時，官方的換算方法（【阿克曼指令】、換算程式）：

```text
R  = H / tan(轉角) + W / 2     （H = 軸距，W = 輪距，左轉的角度為正）
ωz = vx / R
```

- 廠商程式註解：**mini 阿克曼的軸距 H = 0.144 m、輪距 W = 0.162 m**（還沒量測）
- 例：vx = 0.24 m/s、往左 10°，0.322 m 軸距和輪距的車 → R = 1.99 m，ωz = 0.120 rad/s → 送 `00 78`
- 文件說「以右前輪為基準」，但這個公式（加 W/2）在數學上其實是**左前輪**的轉角，和開發手冊的式 3-3 一樣。對控制沒影響，但要知道「轉角」指的是哪一個輪子

### 7.5 文件本身的錯誤（寫測試時發現）

| 地方 | 問題 |
|---|---|
| 1.1 節 | 文字說 Z「順時針為正」，但範例和指令表都是**左轉（逆時針）為正**（和 ROS 的 REP-103 一樣）。以實車為準 |
| 指令表「後退 300 mm/s」 | 寫 `FE D3` = −301，應該是 `FE D4` |
| 指令表「後退 80 mm/s」整欄 | Z 值和文件自己的公式對不起來，大約多了 10 倍。**不要照抄** |
| 3.1 節範例 | 電壓 23.4 V 是大型車的資料，我們的車是 3 串鋰電池（約 10–12.6 V） |

**學到**：廠商文件也會錯。把文件的範例寫成自動測試，就能找到這種錯，也能證明我們的程式和文件一致。

## 9. 安全守則（整理自廠商手冊）

1. **還沒測試完成前，把車架起來讓輪子懸空**（開發手冊 8.3）
2. **禁止堵轉**：輪子卡住時馬達電流會暴增，會燒壞驅動晶片
3. 電源不能超過 17 V、不能反接
4. 板子不能放在金屬表面上，碰板子前先摸接地的金屬放靜電
5. **燒錄程式時不要拔插 USB**，不要改串口晶片的設定
6. 不用時充電口要蓋起來
