# 詳細執行規劃（步驟 7 以後）

2026-10-20 整理。大方向（模組、演算法、實驗的定義）在 [PROJECT_PLAN.md](PROJECT_PLAN.md)；這份把每一步拆成**可以直接照做的小步驟**。做到哪裡看 [STATUS.md](../STATUS.md)。
不排週次，只排**先後**和**誰做**。

**誰做**：
- **Ray**：動手（推車、接線、按鍵盤、量尺寸），還有做決定
- **CC**：Ray 電腦上的 Claude Code（部署、跑不用回答問題的腳本、抓結果回來）
- **chat**：寫程式、寫設定檔、分析數據、更新文件

**每一小步都一樣的流程**：chat 寫好並 push → CC 部署 → 跑（只讀的 CC 自己跑，會動馬達或要人動手的 Ray 跑）→ CC 抓結果回來 → chat 分析、寫 LOGBOOK → 下一步。

桌上（不用車） 10 裝 Nav2（提前做） · 14 AI 的 LLM 部分先在桌上做 · 報告「相關理論」章

**重點調整**：
- 步驟 10（裝 Nav2）不需要車，**提前做**，等電表的時候就可以做。這樣到步驟 11 時不會卡在安裝。
- 步驟 14 的 LLM 部分（自然語言轉成任務清單）也不需要車，可以先做。只是要先等教授決定方向是 A 還是 B。

## 7. 里程計與 IMU 校正

**目標**：odom 直走誤差 < 2%，轉角誤差 < 3%；確認 IMU 方向。
**工具**：`orin_calib.sh`、`analyze_calib.py`（RUNBOOK 6d）。

| # | 做什麼 | 誰 | 完成的標準 / 產出 |
|---|---|---|---|
| 7.1 | ✅ IMU 靜止 60 s + 300 s | CC | gyro z 偏差 0.25°/min；covariance 改成 1e-6 / 1e-4（2026-10-19） |
| 7.2 | 手推直走 **3 次**（每次 1–2 m，Motor OFF，前 3 秒不動） | Ray 推、CC 錄 | 3 個新的 `vx_scale`，彼此差 < 2% → 取平均 |
| 7.3 | 手推**左彎 3 次 + 右彎 1 次**（沿弧線推，不要原地轉） | Ray 推、CC 錄 | gyro z 左正右負 → 確認 `imu_link` 方向；3 個 `wz_scale` 取平均 |
| 7.4 | chat 把新的 `vx_scale`、`wz_scale` 寫進 yaml，部署之後**再推一次直走、一次左彎**驗證 | chat → CC → Ray | 直走誤差 < 2%，轉角誤差 < 3% |
| 7.5 | （Orin 上車之後）用馬達開：直走 1.5 m @ 0.1 m/s；按住 `q` 繞一圈量直徑 | Ray | 馬達開的誤差和手推的差不多；**實際最小轉彎半徑**（韌體寫 0.35 m） → 判斷 60 cm 車道轉不轉得過 |

**要懂的觀念**：系統誤差和隨機誤差的差別；scale 怎麼算；為什麼 `wz_scale` 拿 IMU 當標準。
**報告用**：校正前後的誤差表。

## 8. EKF 融合（實驗 E1）

**目標**：EKF 輸出的位置比「只用輪子」準，而且有數據證明。

| # | 做什麼 | 誰 | 完成的標準 / 產出 |
|---|---|---|---|
| 8.1 | 寫 `wro2026_bringup/config/ekf.yaml` + `localization.launch.py`：`ekf_node`、`two_d_mode`、odom 給 vx（vyaw 看 7.3 的結果決定）、IMU 給 vyaw、30 Hz；feedback 的 `publish_odom_tf: false` | chat | 單元測試：設定檔欄位、TF 只有一個發布者 |
| 8.2 | 部署，車子靜止跑 1 分鐘：`/odometry/filtered` 的頻率、`odom → base_link` 只有 EKF 在發 | CC | 30 Hz；靜止時位置不飄 |
| 8.3 | 寫 E1 的錄製和分析：同時錄 `/odom`、`/imu/data`、`/odometry/filtered`，算三種位置估計（只用輪子、輪子 + gyro 角度、EKF）最後離原點多遠 | chat | `orin_calib.sh loop` + `analyze_calib.py loop` |
| 8.4 | **E1**：在地上貼一個 1 × 1 m 的正方形，手推繞一圈回到原點，**做 5 次**（Orin 上車後再用遙控做 5 次） | Ray 推、CC 錄 | 三種方法的終點誤差（cm）和角度誤差（°），平均 ± 標準差 |
| 8.5 | 如果 EKF 沒有比較好：調 covariance，或者改成融合哪些量 | chat | 調整的過程寫進 LOGBOOK（報告用） |

**要懂的觀念**：預測 / 更新；covariance 決定信任誰；為什麼融合「速度」而不是融合兩個「角度」；`robot_localization` 的 15 格布林矩陣。
**報告用**：E1 的表和軌跡圖（三條線畫在一張圖上）。
