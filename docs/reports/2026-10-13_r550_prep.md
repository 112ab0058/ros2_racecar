## 3. 判斷和原因

1. **base**：PR #1 還沒 merge，所以從 `origin/real/wave-rover-base` 開（遠端那時已有使用者 11:04–11:38 的 6 個文件 commit）。新分支的 upstream 改成 `origin/real/r550-prep`，避免推到 base 分支。
2. **B2**：全清單有移除 → 依規則不給安裝指令並跳過。也**沒有**自己改給「去掉 nav2-bringup 的清單」：規則只允許檢查通過的那份清單，子清單要 Ray 決定。
3. **第三方程式只放 Jetson 的 `~/vendor_ws`**：包含調查用的 WHEELTEC 參考程式（`~/vendor_ws/reference/`，放了 `COLCON_IGNORE`）；Windows 不留副本（Windows 路徑過長也無法下載到暫存區）。
4. **協定 module 的可信度**：沒找到 WHEELTEC 公開的官方文件。兩份第三方程式（2021 ROS 1、2025 ROS 2 Jazzy）核心格式一致；它們都源自 WHEELTEC 原廠 driver（同源），也都不是 R550 的資料，所以只當作「有來源依據的推測」寫 module，標 UNVERIFIED。題目要求「用文件裡的範例封包」，但來源沒有封包範例，測試用的封包是依來源的編碼規則**手算**的；這和 `protocol.py` 來自同一份解讀，所以測試抓不到「整份解讀錯誤」，只能抓編碼實作錯誤。到貨後要用實際錄到的封包補測試。
5. **協定 module 比來源保守**：數值超出 int16 或不是有限值時直接拒絕（C 原始碼會溢位）；接收端一定檢查 XOR（ROS 2 來源有一個繞過條件，沒有採用）。
6. **M10P driver**：build 失敗是缺 apt 套件，不是 Jazzy 不相容，所以沒有改廠商程式。
7. **Foxglove 唯讀**：`capabilities` 只留 `connectionGraph`、`assets`；除了題目要求的 `clientPublish`，也拿掉 `parameters`、`parametersSubscribe`、`services`（否則能從介面改 `max_speed` 或呼叫 service），三個 whitelist 都設成不符合任何名稱。
8. **`ROS_DOMAIN_ID`**：只寫建議，沒改 Orin 的 `~/.bashrc`（要全隊一起換，否則其他電腦會突然看不到 Orin）。
9. **控制器 topic 參數化**：`race_monitor` 也一起參數化（同一個 package，預設值不變）；Gazebo 用的 `sim_race.launch.py` 明確設 `imu_topic: /imu`，讓模擬的接線完全不變。控制邏輯（`core.py`、`tools/`、`test/`、`config/`）和 control 分支相比 0 行差異。
10. **`cmd_vel_units` 的檢查時機**：在建立 controller 時（transport 啟動前）檢查，設錯時 driver 什麼都不送就以 exit code 1 結束；`test_motion` 明確帶 `cmd_vel_units:=pwm`（它的 `--speed` 是 PWM）。
11. **Windows 測試環境**：暫存區的 venv 路徑太長，OpenCV 的平行運算 plugin 載不進來（`cv2.distanceTransform(..., DIST_MASK_PRECISE)` 丟 "Unknown exception"），所以另建短路徑 venv `C:\Users\chaon\rtv`（系統 Python 3.11.9、numpy 1.26.4 和 Jetson 同版、OpenCV 4.10、shapely 2.2.0）跑所有 Windows 測試。這是測試環境問題，不是程式問題。
12. **不在實機跑控制器**：WAVE ROVER 沒有位移 odom、沒有光達，而且題目禁止。
13. **pgrep 自我比對**：Jetson 上第一次用 `pgrep -f` 檢查有沒有 driver 時比對到 ssh 指令本身而中止（什麼都沒啟動）；改成只比對 `^/usr/bin/python3` 開頭的程序。
