# wro2026_imitation

AI 方向 B（模仿學習）：記錄「光達掃描 → 駕駛的動作」，訓練小型神經網路照著開。純 numpy，不需要 torch。示範可以是 Ray 用手機開的，也可以是轉彎規則（`corner.py`，Ray 的過彎技巧寫成程式）開的。

這個 package **不碰串口**。只有 `bc_node` 加上 `publish_cmd:=true` 會發 `/cmd_vel`，而且要 `base_node` 開 `enable_commands:=true` 馬達才會轉，base_node 的限速、0.3 s 逾時、限時照樣有效。

| 檔案 | 用途 |
|---|---|
| `features.py` | 光達掃描變成網路的輸入：前方 ±110°，每 5° 一格，共 44 格，每格是最近障礙物距離 ÷ 3 m。5 種動作：左、直、右、左打滿、右打滿 |
| `dataset.py` | 每一圈掃描對到當下的指令，得到標籤；依時間切訓練和驗證；錄影時的速度和轉彎半徑；找出「輪子在轉、畫面不動」的架空資料 |
| `model.py` | 小型神經網路（44-32-16-5）、Adam 訓練、存讀檔 |
| `extract.py` | `bc_extract`：從 `orin_auto.sh` 的 rosbag 取出訓練資料 |
| `train.py` | `bc_train`：訓練並印出準確率；模型檔裡記下錄影時的速度、半徑、資料來源、驗證準確率 |
| `policy.py` | 安全規則 + 兩種策略：`model`（網路）、`center`（走中間，對照組） |
| `corner.py`、`turn_predict.py` | 轉彎規則（Ray 的過彎技巧）和預測式打滿 |
| `field_sim.py` | 2-D 場地模擬（測試用） |
| `bc_node.py` | `bc_node`：讀掃描，發 `bc/decision`；`publish_cmd:=true` 才發 `/cmd_vel` |

場地上用啟動頁的「訓練」或 `tools/real/orin_train.sh`（取資料＋訓練，見 `docs/real/RUNBOOK.md` 6h 節）。手動：

```bash
ros2 run wro2026_imitation bc_extract ~/r550_map/<time>_auto [更多資料夾]
ros2 run wro2026_imitation bc_train ~/r550_map/*/dataset.npz -o ~/r550_map/model.npz [--source all|hand|rule] [--mirror turns|all|none]
```

**取資料（2026-11-25 起）**：
- 掃描用 `/scan_filled`（光達＋記憶＋相機，跟 `bc_node` 開車時看到的一樣）；舊的錄影沒有它才用 `/scan`。
- 標籤用實際執行的指令 `/cmd_vel_out`，依轉彎半徑分 5 種：小於 0.42 m 算打滿（打滿指令 0.35 m、一般轉彎 0.5 m，取中間）。
- 誰開的：看手機頁的紀錄 `web.log`，「自動」＝規則，按鍵或搖桿＝人。
- 丟掉的資料：撞牆鎖住前 1.5 s（那段開法最後撞牆了）；指令在往前開、但光達畫面 1 秒內變化不到 2 cm 的（架空測試）。

**資料切法**：相鄰的掃描幾乎一樣，隨機切會把幾乎相同的資料同時放進訓練和驗證，分數會虛高。所以依時間切：每 3 秒一段，每 5 段取 1 段當驗證，訓練資料要離驗證段 0.5 秒以上。

**鏡像**（`--mirror`）：把訓練資料左右翻轉一份（輸入反過來、左右標籤對調），驗證資料不翻。光達遮掉自己車子的角度在 168–243°，在 ±110° 之外，所以不會進到輸入。**預設不鏡像**（`none`，2026-11-25）：這台車左右轉向不對稱（打滿左 0.403 m、右 0.292 m；小轉彎左 0.496 m、右 0.373 m，韌體給左輪的角度不夠，LOGBOOK 11-25），翻過去的資料會教錯另一邊的時機。2-D 模擬（`tools/real/sim_bc.py`）：不鏡像逆 8/12、順 12/12；只鏡像一般轉彎 3/12、11/12；全部鏡像 0/12、11/12；只有逆時針資料時順時針 0/12。所以兩個方向都要錄。

## bc_node

```bash
# 只看它會怎麼開（預設，不發 /cmd_vel）；另一個終端機要先開 sensors.launch.py
ros2 run wro2026_imitation bc_node --ros-args -p model:=$HOME/r550_map/model.npz
ros2 run wro2026_imitation bc_node --ros-args -p policy:=center
```

在 Foxglove 看 `/bc/decision`：-1 停、0 左、1 直、2 右、3 左打滿、4 右打滿。`/bc/probs` 是網路對每種動作的機率（舊的 3 種動作模型也能用，只是不會打滿）。

每 0.05 s 依序檢查，第一個成立的決定結果：

1. **太近（too_close）**：任何光達點進到車身外框再加 4 cm 內（車頭在光達前 0.11 m、半寬 0.09 m）→ 停，**鎖住**。解鎖（2026-11-24 起）：先用手機「按鍵」把車開離牆，再按「自動」分頁的「重置」；`bc_node` 只有在最新一張光達資料是新的、而且車身周圍沒有點時才解鎖，解鎖後等下一張掃描才會再開，轉彎策略回到「保持中線」（方向和彎數保留）。重開 bc_node 也會解鎖。
2. **沒有掃描（no_scan）**：最新掃描超過 0.3 s → 停。
3. **掃描格式不對（bad_scan）**：不是從 0° 開始轉一整圈 → 停。
4. 都沒事 → 問策略：左／直／右 → `vx = 速度`、`wz = ±速度 ÷ 半徑`；左／右打滿用打滿半徑（網路模型用錄影時的值，通常 0.35 m）。

**速度和半徑**預設用模型檔裡記的（錄影時用的值，包括打滿半徑），所以網路說「左」時開出來的彎跟它學的一樣。`center` 預設 0.1 m/s、0.5 m。速度超過 0.15 m/s 或半徑小於 0.35 m 會拒絕啟動（0.35 = 方向盤打到底，實際 0.40 m）。數字參數要寫小數點（`speed:=0.10`，不是 `1`）。

**走中間規則**：左邊（+30～+90°）和右邊（-90～-30°）各取最近的牆。前方 ±15° 比 0.5 m 近時，轉向比較空的一邊；不然哪邊的牆近 5 cm 以上就往另一邊轉，否則直走。

**停止**：Ctrl+C、`kill -INT`、`kill -TERM` 都會先送 5 個 0 再結束。程式自己裝了訊號處理，因為腳本在背景啟動的程式會繼承「忽略 SIGINT」（2026-11-10 在 WSL 量到）。

**已知限制**：比 `range_min`（0.1 m）更近的東西光達量不到，輸入會當成很遠；黑色物體看不到。
